# Final first-install READY registration review

This record covers the Runtime-owned PREPARING-to-READY commit coordinator. Stable calls and ownership are in [the installed contract](../../positron_runtime/INSTALLED.md#committing-the-prepared-installation). EXE registry persistence/UI, PXI extraction, installed author launch, update/uninstall and physical power loss are outside this vertical.

## Implementation and corpus

The additive CommitBegin/Step/GetInfo/Cancel/Close handle retains a live PREPARED intent and its actual prepared DB/location when SQL is approved. No-SQL skips DB. It rechecks the complete PREPARING registration, idle retained DB and strict target schema, refreshes registration, attempts one generation+1 CAS and reads back. Unknown outcomes are never replayed; confirmed READY wins cancellation. Closing after CAS without readback retires the intent as UNRESOLVED. Preflight failure preserves PREPARING/data for explicit recovery without implicitly writing FAILED. Normal installed resource/storage admission and explicit Browser registration remain separate.

TEST1385 uses native registration facts and real private PDb files. It covers schema 0/no SQL/non-idempotent migration, retained parents/data, malformed output headers, duplicate children, owner/reentry, exact outcomes and contradictions, lost replies, unreadable readback, competing generation/content, cancellation before/after CAS, READY winning unknown cancellation, unverified close and strict generation overflow. The added twentieth case changes schema through an independent fixture connection after preparation and requires refusal before CAS. Product implementation stays in Runtime; test_host supplies fixtures, native fault injection and assertions only.
